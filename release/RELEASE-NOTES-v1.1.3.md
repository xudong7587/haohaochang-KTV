# v1.1.3 · 收藏夹下载改用应用自己的 B 站取流

以前收藏夹下载走 yt-dlp 的网页解析。平台对 `www.bilibili.com/video/...` 的网页请求返回 404 或反爬页面时，任务就报“视频下载失败，请确认 B站登录 Cookie 和当前账号清晰度权限后重试”，重试也没有改善——同一时间用 API 查询同一个视频却完全正常。本版把收藏夹下载改成和在线找歌、更新画质相同的 API 取流。

- 收藏夹下载使用 `x/player/wbi/playurl` 取独立画面与原唱两条 DASH 轨道，再合成为一个可直接播放的文件，交给原有的整理与分离流程。
- 任务进度里会显示“下载画面／下载原唱”的百分比；同一分 P 重试时能复用已完成的轨道缓存。
- 登录卡片只保留“扫码登录”和“检测登录状态”，去掉手动粘贴 bili-sync 凭证的入口（命令行／接口仍可写入，供脚本使用）。
- B 站以外的来源（例如 YouTube 链接）仍使用 yt-dlp，不受本次改动影响。

## 这次如何更新

只更新 NAS 主镜像，不需要更换 Compose、分离镜像或 APK：

```sh
docker compose pull ktv
docker compose up -d --no-deps ktv
```

ARM64 在两条命令的 `compose` 后加上 `-f docker-compose.arm64.yaml`。CPU／NPU 容器保持原样，主镜像版本可用 `1.1.3` 或 `latest`。

更新后可以直接对之前失败的收藏夹任务点“重试未完成下载”，也可以等下一次同步重新排队；这次不再经过网页解析，平台网页侧的风控不会影响下载。

APK 与 1.1.0.1 功能相同，已经安装的电视、手机和平板不必更新；PC 整理器与分离镜像同样不受影响。
